# Release Notes - OpenL MCP Server v1.2.0

**Released**: August 24, 2026
**MCP Protocol**: 2026-07-28 (modern, stateless over HTTP) — legacy 2025-06-18 retained for existing stdio clients
**Node.js**: ≥24.0.0

OpenL MCP connects your AI assistant to OpenL Studio so you can work with business rules in everyday language. Version 1.2.0 is the largest release since 1.0.0: it adds **branch and merge management**, a **table dependency graph**, an **interactive rule debugger** that replaces the old trace tools outright, and **per-test-case assertion detail**, while hardening how the server talks to Studio and to MCP clients. It also carries the most breaking changes of any release to date — read that section before upgrading.

Part of this work closes out [EPBDS-16132](https://jira.eisgroup.com/browse/EPBDS-16132) ("Agent Experience & Tool Improvements"); the remaining scope of that epic — packaging OpenL MCP as a single installable plugin with bundled skills, auto-generated `AGENTS.md`, and a packaged tracing skill — is carried forward to a follow-up release (see **What's Next**).

---

## At a Glance

| What changed | What it means for you |
|--------------|------------------------|
| **Interactive rule debugger** | Trace tools are replaced: set breakpoints, step through a calculation, inspect live frame variables, and watch specific cells across an entire run |
| **Branch & merge tools** | Discover repository-wide merge targets, inspect BASE/OURS/THEIRS conflicts read-only, and delete obsolete branches or projects with confirmation |
| **Table dependency graph** | See a table's datatype/vocabulary relationships and value details, filtered by project layer |
| **Run a table directly** | Execute a table with a test case or JSON input and get bounded, deduplicated results without polling |
| **Per-test-case detail** | Markdown test results now show which specific test unit failed and its expected vs. actual values |
| **Structured JSON by default** ⚠️ | Tool responses default to JSON instead of Markdown — a breaking change for anything parsing text output |
| **PAT-only, no more login/logout** ⚠️ | Browser-based sign-in and the credential cache are removed |

**Tool count**: 74 tools, up from 56 in v1.1.0 — 23 added, 5 removed (the old trace-tree tools, replaced by the debugger). Verify the exact count for your build with `openl-mcp --list-tools` before quoting it externally.

> **Note for IT and developers**: this release includes five breaking changes (default response format, table content shape, two changed tool signatures, and one removed tool) plus the removal of browser-based login. See **Breaking Changes** and **Migration Notes** before upgrading from v1.1.0.

## Breaking Changes — Read First

| Change | Action required |
|--------|------------------|
| **Structured JSON is now the default response format** | Tool responses return structured JSON instead of Markdown by default, so results can be reused safely in later tool calls. If your integration parses Markdown text, pass the appropriate explicit `response_format` value to keep the old behavior. |
| **Tables are exposed only as `RawSource`** | `openl_get_table` always returns raw cell-matrix content. `openl_create_project_table`, `openl_update_table`, and `openl_append_table` reject the older typed table DTOs, which could lose workbook structure on round trips. Update any code that built typed table objects to build a `RawSource` matrix instead. |
| **`openl_repository_project_revisions` signature changed** | Now requires the stable `projectId` from `openl_list_projects`. `repository`, `projectName`, and `branch` parameters are no longer accepted. Look up the `projectId` first if you were passing those. |
| **`openl_create_project` COPY mode signature changed** | `template` must now be the exact source `projectId` from `openl_list_projects`, not a project name — this disambiguates duplicate business names across mapped repositories. Resolve the `projectId` before calling. |
| **`openl_resolve_merge_conflicts` is removed** | Studio doesn't expose a sufficiently safe API for autonomous conflict resolution. Use `openl_get_merge_conflicts` / `openl_read_merge_conflict_file` to inspect BASE/OURS/THEIRS evidence, then resolve manually in Studio. |
| **Browser-based `openl-mcp login` / `logout` and the credential cache are removed** | Authentication is now explicit-token-only: set `OPENL_PERSONAL_ACCESS_TOKEN` or pass `--token`, otherwise the server runs anonymous (single-user Studio). Generate a PAT in OpenL Studio under **User Settings → Personal Access Tokens**. Delete any leftover `~/.config/openl-mcp/credentials.json` manually — it's no longer read. |
| **The old trace tools are gone** | `openl_get_trace_nodes`, `openl_get_trace_node_details`, `openl_get_trace_parameter`, `openl_cancel_trace`, and `openl_export_trace` are removed. See **Migrating trace workflows** below for their replacements. |

## What's New for You

### Business Analysts, Rule Authors, and Branch Owners

**Manage branches without leaving the conversation** — Discover which base branch a project can merge into even before that branch holds the project (*"What can I merge this branch into?"*), inspect a merge's conflicts read-only by BASE/OURS/THEIRS evidence, and delete an obsolete branch or an entire project once you've confirmed the name.

**See what a table depends on** — *"What does the Auto Rating datatype depend on, and what depends on it?"* — the dependency graph now includes datatype and vocabulary relationships with their values, filterable by project layer.

**Run a table on demand** — *"Run the Premium Calculation table with this test case and show me the result"* — one bounded call instead of a manual start-and-poll workflow.

**Trust binary file round trips** — reading and writing binary project or conflict files (e.g. attachments) now uses lossless base64 in a JSON envelope, so binary content survives a round trip exactly.

### QA Teams and Testers

**The trace tools are now an interactive rule debugger.** This is the single biggest change in the release, and it's a full replacement, not an addition:

- *"Start a trace for the Premium Calculation table and stop at the first breakpoint"* — `openl_start_trace` runs to the first stop, with optional initial breakpoints, a test case or JSON input, input replay, and profiling.
- *"Step into the next rule call"* / *"step over"* / *"step out"* — `openl_step_trace`.
- *"Resume until the next breakpoint or exception"* — `openl_resume_trace` waits inside the call instead of returning immediately.
- *"Show me the live variables in this frame, and highlight the decision table cell that fired"* — `openl_inspect_trace_frame`.
- *"Set a breakpoint on the Auto Rating table, but only on its third execution"* — `openl_set_trace_breakpoints` supports table name, URI, spreadsheet cell, "any", or a specific fired rule, plus an `@N` suffix for a specific iteration.
- *"Watch the Fleet Discount cell across the whole run"* — `openl_watch_trace_cells` returns one series per cell, including cells inside lazy result branches, capped and reported so a combinatorial branch can't overflow the response.
- *"Expand this profiling branch"* — `openl_expand_trace_tree` pages a huge run's call tree one level at a time instead of serializing it whole.
- `openl_get_trace_value` expands a lazy value; `openl_stop_trace` ends the session.

Profiling now returns a constant-size top-N-slowest-tables overview instead of a full tree that can exceed the 1 MB tool-result limit — a real project's trace dropped from roughly 1 MB to about 6 KB.

**Read large tables in slices** — `openl_get_table` now supports `startRow`/`maxRows` for windowed reads of a large table (reporting `totalRows`), plus `styles: true` for each cell's Excel formatting (color, bold/italic/underline, alignment, indent, borders). A windowed response can no longer be passed back into `openl_update_table` — a safeguard against silently deleting the rows you didn't happen to read.

**See exactly which test case failed** — Markdown test-result responses now identify each returned test unit and show failed assertions with expected vs. actual values (previously it was harder to tell which case among several had failed).

### Operations, Security, and Platform Teams

**Restrict which tools a deployment serves** — the new `OPENL_MCP_TOOLS` environment variable is an optional server-side allow-list. Unset (the default) changes nothing. Set to a comma-separated list (bare or `openl_`-prefixed names), only those tools are listed and callable; anything else answers `MethodNotFound`. A read-and-diagnostics subset of 39 tools cuts the schema payload a client receives from roughly 169 KB to 85 KB. Note that setting the variable but naming no tool (empty string, whitespace, a lone comma) serves *nothing* and logs why — intentionally: a restriction setting must not fail open.

**OAuth2 Bearer tokens now reach Studio unmodified** — the new `OPENL_MCP_PRESERVE_AUTH_SCHEME` flag (HTTP transport, off by default) presents an inbound `Bearer` credential to Studio as `Bearer` instead of rewriting it to `Token`. Without it, a Studio running in OAuth2 mode couldn't authenticate an IdP access token forwarded through this server. With the flag on, the server logs once that it is forwarding a caller-supplied credential without validating it — full JWT validation and RFC 9728 resource metadata are not part of this change.

**Identify exactly which build is running** — `openl_get_version` reports the server's version and build identity (commit, branch or tag, build time, Node.js version, platform). The same information now appears in `openl-mcp --version`, the startup logs, and the HTTP `/health` response — useful for tying a support ticket to an exact build.

**Streamable HTTP is stricter and more isolated** — browser requests from origins outside the explicit `MCP_ALLOWED_ORIGINS` allowlist are now rejected; `Mcp-Session-Id` is exposed to approved browser clients; and every anonymous legacy MCP session now gets its own Studio HTTP client instead of sharing one.

**A dependency vulnerability is patched** — the transitive `@hono/node-server` dependency is updated to a release patched against the Windows `serve-static` path-traversal advisory (GHSA-frvp-7c67-39w9).

## New and Changed Tools

**23 new tools:**

| Category | Tools |
|----------|-------|
| Branching & merging | `openl_list_project_branches`, `openl_merge_project_branches`, `openl_check_project_merge`, `openl_get_merge_conflicts`, `openl_read_merge_conflict_file`, `openl_cancel_merge_conflicts`, `openl_delete_project_branch` |
| Project/table lifecycle | `openl_delete_project`, `openl_copy_table` |
| Table workflow & discovery | `openl_run_table`, `openl_get_table_dependencies`, `openl_list_module_sheets`, `openl_list_project_modules`, `openl_list_table_property_definitions` |
| Interactive rule debugger | `openl_step_trace`, `openl_resume_trace`, `openl_inspect_trace_frame`, `openl_set_trace_breakpoints`, `openl_get_trace_value`, `openl_expand_trace_tree`, `openl_watch_trace_cells`, `openl_stop_trace` |
| Diagnostics | `openl_get_version` |

**5 tools removed** (superseded by the interactive debugger above): `openl_get_trace_nodes`, `openl_get_trace_node_details`, `openl_get_trace_parameter`, `openl_cancel_trace`, `openl_export_trace`.

**Reworked in place** (same name, changed behavior — see Breaking Changes): `openl_get_table` (RawSource-only, windowed reads, styles), `openl_repository_project_revisions` (stable `projectId` only), `openl_create_project` (COPY mode needs `projectId`; blank mode now accepts a target branch and copies use Studio's atomic indexed copy API instead of ZIP download), `openl_start_trace` (now the entry point into the interactive debugger).

## Fixed Bugs

- CLI output piped into another command (`openl-mcp --list-tools | jq …`) no longer gets cut off after roughly 64 KB — the process previously exited before stdout had drained.
- `openl_list_project_branches` now supports repository-wide merge-target discovery, so a project created on an isolated branch can be merged into a base branch that doesn't hold that project yet.
- `openl_append_table`/`test-start`/`deploy`/`redeploy` tools no longer advertise themselves as idempotent, preventing MCP clients from treating repeatable side effects as safe automatic retries.
- Table writes now reject read-only cell styles instead of reporting success while Studio silently ignores the formatting change.
- `openl_search_project_files` now documents Studio's text-only boundary instead of implying binary contents (XLSX, ZIP) are indexed.
- Large single-object JSON responses are replaced with a bounded, valid-JSON preview instead of exceeding the response limit while incorrectly claiming to be truncated.
- Markdown responses from `openl_get_table_dependencies` now render dependency/dependent edges, table metadata, and query context instead of collapsing the graph into a flat table list.
- `openl_project_status` defaults to waiting for a conclusive result and lazily starts compilation when Studio initially reports `idle`; pass `wait: false` for the old immediate-snapshot behavior.
- `openl_create_project` now returns the same opaque backend `projectId` as `openl_list_projects` instead of mislabeling the project name as its ID.
- `openl_list_projects` and `openl_list_tables` now preserve Studio's true pagination metadata (`total_count`, `has_more`, `next_offset`) instead of re-paginating a single backend page.
- The HTTP / Streamable HTTP request-body cap is raised from Express's 100 KB default to 5 MB (override with `MCP_MAX_BODY_SIZE`), so a large trace `inputJson` or table payload is no longer rejected with HTTP 413 before it reaches the MCP handler. Does not affect stdio (unbounded).
- Raw table-action validation is tightened: `cells` is now required for the row/column edit tools, and the delete tools reject `position: 0` (the header row / leading-label column) with an actionable local error instead of an opaque backend response.

## Known Issues

- **Tool count varies by build** — the exact number of tools a given deployment serves depends on the `OPENL_MCP_TOOLS` allow-list setting; the 74/23-new/5-removed figures above describe the unrestricted default.
- **Same limitations carried from v1.1.0**: some Git-based repository operations still require the project to be open in OpenL Studio first; very long tool responses are still trimmed with guidance to request more detail in smaller pieces; a branch-specific project copy may not appear in project lists until Studio re-indexes the repository; blank new projects are still created on the repository's default branch (this release adds an optional target branch for blank projects — see **What's New for You** — but the default is unchanged).

## Migration Notes

### From v1.1.0

**1. Response format** — if your integration parses tool output as Markdown text, pass the appropriate `response_format` value explicitly; the unqualified default is now structured JSON.

**2. Table payloads** — replace any typed table DTO construction with a `RawSource` cell-matrix payload before calling `openl_create_project_table`, `openl_update_table`, or `openl_append_table`.

**3. `openl_repository_project_revisions` calls** — resolve the project's `projectId` via `openl_list_projects` first; `repository`/`projectName`/`branch` arguments are no longer accepted.

**4. `openl_create_project` COPY mode** — resolve the source project's `projectId` via `openl_list_projects` and pass it as `template`; project names are no longer accepted there.

**5. Authentication** — replace any reliance on `openl-mcp login`/`logout` or the cached credential file with an explicit `OPENL_PERSONAL_ACCESS_TOKEN` / `--token`, generated in OpenL Studio under **User Settings → Personal Access Tokens**.

### Migrating trace workflows

| Removed | Replace with |
|---------|---------------|
| `openl_start_trace` (old immediate-tree behavior) | `openl_start_trace` (same name — now runs to the first stop and takes breakpoints) |
| `openl_get_trace_nodes` / `openl_get_trace_node_details` | `openl_inspect_trace_frame` (live frame variables and decision outcome) |
| `openl_get_trace_parameter` | `openl_get_trace_value` (expand a lazy value) or `openl_inspect_trace_frame` |
| `openl_cancel_trace` | `openl_stop_trace` |
| `openl_export_trace` | `openl_expand_trace_tree` (page the executed call tree) combined with `openl_inspect_trace_frame` |

There is no automatic mapping for step-by-step tree walking — the new debugger is breakpoint- and stack-frame-based (`openl_step_trace`, `openl_resume_trace`), not tree-based, so trace-consuming code built around the old tree endpoints needs to be rewritten against the debugger model, not just re-pointed at new tool names.
